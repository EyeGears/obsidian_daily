# Echosystem — Код

Связанные разделы: [[echosystem/Геймдизайн.md|Геймдизайн]] · [[echosystem/Сюжет.md|Сюжет]] · [[echosystem/Арт.md|Арт]] · [[echosystem/dizdoc.md|Хаб диздока]]

## Технические цели MVP
- Поддержать рейд на 1–4 игроков с принудительным переходом на арену босса.
- Реализовать «узлы связи» как серверно-валидируемые объекты прогрессии региона.
- Обеспечить быстрый runtime-тюнинг оружия, модулей и врагов через data-driven таблицы.

## Архитектура систем
1. **Raid Session Manager**
   - Создаёт сессию, запускает таймер, следит за условиями эвакуации.
   - При завершении переводит команду на boss-instance.
2. **Encounter Director**
   - Спавн волн, элиток и событий по параметрам биома и «уровня шума».
3. **Connection Node System**
   - Захват/апгрейд узлов связи, региональные бафы, открытие маршрутов.
4. **Build & Loadout Service**
   - Ядро оружия + 2 основных модуля + 1 сервис-слот.
5. **Narrative Trigger Bus**
   - События сюжета (реплики, радио, квестовые флаги) через единый шина-сигнал.

## Сетевая модель
- Host-authoritative (или выделенный сервер на production).
- Репликация:
  - Позиции игроков/врагов.
  - Состояния узлов связи.
  - Таймер рейда и глобальные модификаторы.
- Антидюп для лута: предмет считается добытым только после серверного подтверждения.

## Пайплайн контента
- Конфиги в JSON/таблицах:
  - `weapons` (архетипы, урон, stagger, расход).
  - `modules` (эффекты, стоимость, энергопотребление).
  - `enemies` (роли, AI-профиль, резисты).
  - `boss_phases` (триггеры и уязвимости).
- Именование ID: `eco_<category>_<name>_<tier>`.

## Инструменты для команды
- Внутриигровой debug-overlay:
  - текущий seed рейда,
  - таймер,
  - агро-таблица,
  - latency и packet loss.
- Режим «симуляции рейда» для быстрой проверки баланса без полного прохождения.

## Риски и техдолг
- Синхронизация массовых AI-столкновений в коопе.
- Пиковая нагрузка в фазе 2 босса (активация 3 узлов одновременно).
- Необходимость early profiling до добавления сезонных модификаторов.
